## なぜ塞げないのか（uid が1つ・A-1〜A-3・gh auth token）

- **なぜ塞げないのか。** SDK の子プロセス（マネージャー・作業者・MCP・`Bash` の子）は**ただ1つの uid** で起こされる（`packages/core/src/runner.ts` の `spawnAsUser`。渡される `#childUser` は1つしか無い）ので、**ファイルの mode では「資格を読む主体」と「作業者」を分けられない。** 置き場を変えても（A-1）、ファイルを捨てて env だけにしても（A-2）塞がらず、**器の分類器と同じ門を作業者の層にも立てる案（A-3）は、同じ入力を1回目に拒んで2回目に通した実測が在るので「弾いていないこと」を測る歯が書けない。**⟹ 🔑 決定打は `gh` 自身が `gh auth token` を持つことで、**作業者が `gh` を打ってよい限り、鍵は届く**（#888 の逐語: 「**「`gh` を使わせる」と「`gh` の鍵を読ませない」は、同じ uid・同じプロセス族の中では両立しない**」）
