## 実例（PR #155・PR #1167）: actor から層を推定して誤った

- **実例（2026-08-22T00:03:41Z 観測）**: PR #155 の `ready_for_review` の actor は `takecchi` だが、**打ったのは人間ではなくクローンである。** このとき PR を書いたマネージャーは「自分は打っていない」ことから自動経路を疑い、**範囲外として依頼者へ渡した。** もし自分で timeline を取って「actor が人間だから人間がやった」と結論していたら、**同じだけ誤っていた** — actor は「誰が打ったか」ではなく「誰のトークンで打たれたか」しか答えない
- **⚠️ その「もし」が実際に起きた（2026-09-17T07:20Z、PR #1167）。** マネージャーがマージした PR を、**同じ委譲の作業者が「human/`takecchi` による直接マージ」と報告した。** 取った材料は正しい —— `gh pr view --json mergedBy` が `{"login":"takecchi"}`、timeline の `merged` / `closed` の actor も `takecchi` である。**読み方だけが違った。**
  - **出発点も正しかった** —— 「自分は打っていない」から始めている。**分岐したのはその次で、`mergedBy` を根拠に「では人間が打った」へ進んだ。** ⟹ 上の PR #155 の人は同じ地点から「自動経路を疑い、範囲外として渡す」へ進んだ。**同じ材料から、逆の結論へ行ける。**
  - ⛔ **この作業者の文脈には、この節を含む本文が全文載っていた**（自己申告と、載った時機の報告が在る）。⟹ **書いてあっても踏む。**「規約に書くことは必要条件であって十分条件ではない」（#1046）と同じ形である
  - **観測できたのは、作業者が「自分はマージしていない」を報告に書いたからである。** 書かなければ、誤った帰属がどこにも現れないまま残った
