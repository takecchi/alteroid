# ADR 0071: Phase 2 の作業選定を自律エージェントへ委譲する。境界は「取り消せるか」で引く

- **状態**: 採用 (2026-09)

- **⚠ 先に書く — この ADR が決めていないこと**:

  **Phase 2 に何を入れるかは、この ADR では1つも決めていない。**
  決めたのは**選び方**と**境界**だけである。候補そのものは `docs/roadmap.md` §3 に既に在る。

- **文脈**:

  Phase 1 は完了し（段階1〜7）、`docs/roadmap.md` §5 の設計判断6項目も
  2026-09-06 のオーナー回答ですべて解決済みである。**⟹ 進行を止めているものが無い。**

  一方で、このリポジトリは既に **[alteroid](https://github.com/takecchi/alteroid) によって
  24時間、自律エージェントが改修を進めている。**この ADR を書いている作業者は、
  同じ時間帯に PR #78〜#84 が入り、自分の作業ブランチに
  **自分が push していないコミットが現れる**のを観測した（当初は原因不明として報告した）。

  オーナーの逐語の要求:

  > **「Phase 2 に何を入れるか決めて実装まで進められる状態にしたいんだよね」**
  > **「今この場で決めるのではなく AI が勝手に決めて勝手に実装進められる状態、指示にしておいてほしい」**

  **これはオーナーの決定である。**

  既存の規約（`AGENTS.md`）は「§5 に無いものは設計側で決めて理由を残す」と既に述べており、
  **Phase 2 の項目選定はもともと作業側の裁量に入っていた。**足りなかったのは
  「どれから取るか」の順序と、**訊けない状況での止まり方**である。

- **決定**:

  **1. 選び方を4段の優先順で固定し、`docs/autonomy.md` に置く。**

  1. 壊れているもの（CI が赤い / 使う人に実害が届いている）
  2. **北極星の物差しを動かすもの**（「使う側が会話ログを全部積むのをやめられたか」）
  3. 2 の前提になっているもの
  4. 測れていないものを測る

  **4段すべてが空なら着手しない**——「やることが無い」と報告して止まる。
  **物差しを動かさない機能を足すより良い。**

  **2. 段2 に入るには、着手前に3つの問いへ答えられること。**

  「何の数字が動くか」「どう測るか」「動かなかったらどうするか」。
  **3つ目に「動かなくても入れる」と書きたくなったら、それは段2ではない。**

  **3. 境界は「取り消せるか」で引く。**

  ⛔ にしたのは、**やり直しが効かないか、製品の性格を決めるもの**である:
  PR のマージ / publish・Release・npm 側の設定 / 版を手で上げること /
  北極星の書き換え / 公開 API の破壊的変更 / ライセンス・名前 / §5 級の判断。

  **⚠ 「危ないから」ではなく「取り消せないから」で選んだ。**
  実装の是非やスキーマ変更は、間違えても PR を閉じれば戻る——だから ⛔ に入れていない。
  `npm publish` は戻らない（`0.1.0` は上書きできない形で残っている。ADR 0066）。

  **4. 判断が要るのに材料が無いときは、§5 へ項目を足して止まる。**

  見分け方も書いた——「どちらを選んでも技術的には成立するが、
  選び方が製品の性格を決める」なら §5 行きである。

  **5. 実際に踏まれた穴を6つ、手引きに列挙する。**

  ADR の「引き受けた負債」に散っていて、**次に走るエージェントが読む順路に無かった**もの:
  ADR 番号の衝突（1セッションで3回）/ `git checkout` で未コミットの編集が消える /
  手元の `test` が DB 段を飛ばす / 手元の `pack:check` だけが赤くなる /
  擬似 provider の MRR 0.018 を性能と読む / `npm view` で publish の成否を判断する。

  **6. `AGENTS.md` からは指すだけにする。**

  `AGENTS.md` は「北極星の要約を置かない」と自ら定めている
  （**複製した瞬間から正文と要約はずれ始める**）。同じ理由で、
  この手引きの中身を `AGENTS.md` へ写さない。

- **採らなかった案**:

  | 案 | 却下の理由 |
  |---|---|
  | **この ADR で Phase 2 の項目を決めてしまう** | **オーナーが逐語で「今この場で決めるのではなく」と言った。**加えて、選定を1回のスナップショットで固定すると、**壊れているものが出たときに順序が守られない**——4段の優先順は、そのつど再評価される形でないと意味が無い |
  | **`docs/roadmap.md` §3 に順位を書き込む** | 同じ理由。§3 は「Phase 1 の土台が後続をどう安くしているか」を書く場所であり、**着手順を書く場所ではない。**混ぜると、順序が変わるたびに §3 を書き換えることになる |
  | **手引きを `AGENTS.md` に直接書く** | 決定6。`AGENTS.md` は指す文書である |
  | **⛔ の境界を「危険かどうか」で引く** | 「危険」は読む人によって動く。**「取り消せるか」は動かない。**PR を閉じれば戻るものと、registry に残るものは、はっきり分かれる |
  | **マージも委譲する** | オーナーが「マージまでしちゃっていいよ」と言った場面は在ったが、**それは特定の PR に対する許可であって、恒常的な委譲ではない。**恒常化するならオーナーが明示的に決める |
  | **穴の一覧を作らず、各 ADR の「負債」節を読ませる** | 実際に読まれなかった。**ADR は69本あり、負債節は散っている。**次に走る者が最初に読む場所に置くほうが効く |

- **⭐ 測ったこと — 手引きを書いた本人が実行して、2つ穴が出た**

  「書けたか」ではなく「**使えるか**」を測るため、作業者が自分で4段を実行した。**2つ落ちた。**

  **穴1: 段で当たった項目が ⛔ だったときの行き先が無かった。**

  段1（壊れているもの）を実行したところ、**空ではなかった** 【実測】——
  npm 上の `@mnemora/*@0.1.1` の README が「CommonJS の `require` からは読み込めない」と
  出しており、これは誤りである（Node 22.12+ では読み込める）。git 側は PR #86 で直っているが、
  **届けるには Release が要る＝ ⛔ である。**

  **⟹ 段1 が空でないのに手が出せない。**初版の手引きはこの場合を書いておらず、
  読んだエージェントは「飛ばす」か「止まる」かを自分で決めることになっていた。
  **飛ばせば優先度の高いものが黙って落ちる。**
  ⟹ §1.0 を足した——**報告に明記してから次へ進む。**

  **穴2: 測れない環境で段2・段4 が「空」に見えてしまう。**

  段2・段4 は実測を要求する。`examples/chat` のベンチを DB 無しで起動して確かめた 【実測】:

  ```
  Error: DATABASE_URL が設定されていません。mnemora は Postgres + pgvector を要求する
  ```

  実 API のキーは要らない（カセットが repo に在る）が、**DB は代替できない。**
  **⟹ DB を持たない環境では段2・段4 は「空」ではなく「判定不能」である。**
  空として扱うと「やることが無い」へ倒れ、**本当に必要なもの（DB を用意すること）が
  誰にも伝わらない。**⟹ §1.1 を足した——**「測れなかった」と報告する。**

  **⚠ この2つは、書いただけでは出なかった。実行して初めて出た。**

- **引き受けた負債**:

  - **この手引きが守られているかを検査する歯は無い。**規律である。
    ⛔ の項目（マージ・publish）は GitHub / npm 側の権限で縛るほうが確実だが、
    **この ADR ではそこまで踏み込んでいない**（branch protection と npm の設定は
    オーナーの領分であり、⛔ に自分で挙げた「してはいけないこと」に当たる）。
  - **4段の優先順は、段1（壊れている）が空かどうかの判定を人の目に依存している。**
    「使う人に実害が届いている負債」を機械的に選り分ける仕掛けは無い。
  - **並行して走るエージェント同士の衝突は、`gh pr list` を見る規律でしか防いでいない。**
    ADR 番号の衝突は「PR 直前に取る」で緩和するが、**同じ項目に2人が着手することは防げない。**
  - **`docs/autonomy.md` 自身が古くなる。**穴の一覧は「実際に踏まれたもの」なので、
    新しい穴が踏まれるたびに足す必要がある。**足す規律を保証する仕掛けは無い。**

- **これが覆るとしたら**:

  - **オーナーがマージや publish も委譲すると決めたとき。**決定3 の ⛔ が縮む。
  - **物差しを動かす項目が尽きたとき。**段2 が恒常的に空になり、
    4段の優先順そのものを組み直すことになる。
  - **並行エージェントが増えて、`gh pr list` を見る規律で衝突を防げなくなったとき。**
    作業の予約（issue の assign 等）という別の仕掛けが要る。

- **確かめたこと / 確かめていないこと**:

  - **確かめた（この器で実行）**: `docs/roadmap.md` §5 の6項目がすべて解決済みであること
    （§5 前書きの逐語）。Phase 2 の候補5項目が §3 に在ること。
    現在の ADR 最大番号が `0070` であること。開いている PR が0件であること。
    `docs/autonomy.md` に挙げた穴6件の出所を1件ずつ辿った——
    ADR 0015（DB 段の告知）/ ADR 0051（provider の三層）/ ADR 0066 の測ったこと7・8
    （`git checkout` の事故・`npm view` の遅れ）/ ADR 0070（版の権威）/
    ADR 0068 と `examples/chat/README.md`（arm A の MRR 0.018）/
    ADR 番号の衝突はこのセッションでの実測（3回）。
  - **確かめていない**: **この手引きに従って自律エージェントが実際に動くこと。**
    書いただけで、走らせていない。**⟹ 最初に読んだエージェントが、
    読みにくい・判断できないと感じたら、それはこの文書の欠陥である。**直して良い。
  - **確かめていない**: alteroid がこの文書を読む経路に在るかどうか。
    `AGENTS.md` から指してはいるが、**alteroid が `AGENTS.md` を読むことは
    オーナーの申告であって、この作業者が確認したものではない。**
