# 北極星 — alteroid は何の代替か

> **人間が PC の前に座り、Claude Code に作業を依頼して物事を進める。**
> alteroid はこれを、人間の代わりにクローン（AI）が行うようにするためのツールである。

一文で言えば: **クローンは「Claude Code を使う人間」の代替であって、「制限された自動化ジョブ」ではない。**

この文書はプロダクトの全ての判断の基準（正典）である。実装・レビュー・設計の議論が迷子になったら、ここへ戻る。個別の要件はこの文書から導出され、[PRD.md](./PRD.md) 以下に規定される。矛盾したらこの文書が勝つ。

## 置き換えの対応

人間の思考は上位モデル（Fable 等）がコピーし、クローンとなる。「人間 → Claude Code」の関係が「クローン → マネージャー」に写る。

| 元の世界 | alteroid の世界 |
|---|---|
| 人間 | クローン（人間の価値観をコピーした AI） |
| 人間が使う Claude Code | マネージャー（+ コストと文脈のために切り出された作業者） |

例えば、人間が普段やっていることがそのままクローンの仕事になる:

- 人間＝クローンがアイデアを出して AI に相談する
- 人間＝クローンが AI に「Web で調べてほしい」と調査を依頼する
- 人間＝クローンが AI に実装指示を出す

このように、**クローンが人間に成り代わって勝手に物事が進む**のがゴール。人間の役目は価値観の伝達と最終承認だけに縮む。

## 2つの禁止（このプロダクトの憲法）

1. **デグレード禁止** — 人間が Claude Code に対してできることが、この階層でできないなら、それは仕様ではなく**バグ**である。「できなくてよい」と書いた時点で北極星から外れている
2. **追加制限禁止** — 「人間が PC を使って Claude Code に指示を出した際」に無い制限を足さない。制限が必要なら、能力（ツール一覧）を削るのではなく、**方針**（何をさせないかの宣言）と**実行環境の境界**（サンドボックス・ネットワーク・認証情報の配布範囲）で表す。方針は設定で開けられなければならない

要件としての精密な定義は [PRD.md「能力の等価性」](./PRD.md#非機能要件-能力の等価性デグレード禁止) と [「業務範囲」](./PRD.md#業務範囲-代行するのはコーディングだけではない) にある。

### 適用範囲 — 2つの禁止はどこに効くか

2つの禁止は**すべての層に効く**。「人間 → Claude Code」の写像先（マネージャーと、そこから切り出された作業者）だけでなく、**クローン自身にも効く**。例外は無い。

クローン自身は Claude Code ではなく**人間**の写像である。そして**人間は道具を持たない存在ではない** — PC の前に座った人間は、Claude Code に頼むだけでなく、自分でも端末を叩き、ファイルを開き、ブラウザで確認する。したがって「クローンは人間の写像だから道具を持たない」は写像として成り立たない。**人間が自分の手でできることは、クローンも自分でできる。**

その上で、クローンは重い調査・実作業を**原則としてマネージャーへ委ねる**。理由は長寿命セッションの俯瞰と判断を守るためであり、これは禁止2の言う**方針**である（[PRD「層ごとの能力」](./PRD.md#層ごとの能力削るのではなく役割で分ける)）。方針であるから、必要だとクローンが判断した場面では自分で手を動かしてよく、**道具を取り上げて委譲を強制してはいけない**。「人間は普段 Claude Code に任せるが、自分で見た方が早いときは自分で見る」——その自由まで含めて写像である。

この線引きを**新たな例外の言い訳に流用してはいけない**。「委譲が原則なのだから道具は要らない」という推論は禁止2そのものの否定であり、どの層であれ能力を絞った瞬間に北極星が壊れる。

## 立ち戻るための問い（実装・レビューの冒頭で必ず問う）

すべての変更とレビューは、この問いを通してから始める。

- [ ] この変更のあとも「人間が Claude Code でできること」は全部できるか？　できないものを「仕様」「スコープ外」と書いていないか（それはバグである）
- [ ] 制限を**能力の削除**（`tools` を絞る・ターン数上限・パス封じ込め）で実現していないか？　方針と実行環境の境界で表しているか？
- [ ] **クローンの道具を「委譲が原則だから」で削っていないか？**　委譲は方針であり、能力の欠落として実装してはいけない（上の「適用範囲」）
- [ ] 「安全のため」「コストのため」「壊れると怖いから」を理由に能力を削っていないか？　安全は**境界**で、コストは**委譲とモデル選択**で解決する
- [ ] 仕事の型を「実装専用」に狭めていないか？　人間が Claude Code に頼むのは実装だけではない（調査・設計の相談・外部サービスの確認・レビュー）
- [ ] エージェントへの指示・システムプロンプトに、作者の一運用スタイル（「検証は CI で」等）を**要件のように**書いていないか？
- [ ] 階層を潰す・安いモデルへ寄せる「最適化」をしていないか？　役割とモデル帯の対応（クローン = Fable、マネージャー = Opus、作業者 = Sonnet）は固定の設計判断であり、変更には人間の承認が要る
- [ ] 「どこまで人間に確認するか」を設定項目や行為の一覧で表そうとしていないか？　その違いこそクローンが記憶として持っているものである（[PRD「権限境界」](./PRD.md#要件-権限境界クローンが判断する)）
- [ ] 人間が起点にならないと動けない形を「仕様」にしていないか？　北極星は「クローンが人間に成り代わって**勝手に**物事を進める」ことである（要件は [PRD「自律」](./PRD.md#要件-自律仕事の起点は人間に限らない)）
- [ ] 境界（サンドボックス・ネットワーク・認証情報）の導入が、実質のデグレードになっていないか？　境界を入れた側が「人間が Claude Code でやる典型作業が境界の下で完遂できる」ことを示す
